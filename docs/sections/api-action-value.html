AviFlow.action

AviFlow.action.value(element, event?, targetSelector?, flow?)

AviFlow.action.value(element: HTMLElement, event?: HTMLEvent | null, targetSelector?: string, flow?: AviFlow instance) → string | boolean | null

Registered by default as AviFlow.action.value (implemented by AviFlowActions.elementValue). Reads the current value of the element that triggered the flow. Synchronous, no side effects. Returns null if element is falsy or nothing can be read.

Value resolution

ElementReturns
<input type="checkbox">true if checked, false otherwise (boolean, the value attribute is ignored).
Any element whose value property is a string (<input>, <textarea>, <select>, <button>, radio inputs...)The value (string). An empty control returns "", not null.
Any other element (<div>, <span>, <p>...)Its innerText (string).
No element, or no readable value / innerTextnull.

Resolution stops at the first match, in the order shown above.

Arguments

ArgumentUse
elementThe element that triggered the flow. The only argument used.
event, targetSelector, flowAccepted for compatibility with the standard action signature, but ignored.

Examples

FlowResult
data-flow="input -> value -> #preview"On every input event, the field's text is sent to #preview.
data-flow="change -> value -> #state"On a checkbox, true or false is sent to #state.
data-flow="click -> value -> #out"On a <div>, its innerText is sent to #out.
data-flow="change -> value -|"Reads the value but updates no target (useful with a custom wrapper action).

Notes

  • Radio inputs return their value, not their checked state. Only checkboxes return a boolean.
  • Elements whose value property is not a string (e.g. <li>, <meter>, which expose a number) fall back to innerText.
  • A <button> without a value attribute has an empty string value and therefore returns "", not its label.
  • <select multiple> returns the value of the first selected option only.
  • Can be overridden by passing your own value action to the AviFlow constructor.
