AviFlow.action

AviFlow.action.fetch(element, event?, targetSelector?, flow?)

AviFlow.action.fetch(element: HTMLElement, event?: HTMLEvent | null, targetSelector: string, flow: AviFlow instance) → Promise<Object|string> | null

Registered by default as AviFlow.action.fetch. Reads configuration from the element and performs an HTTP request. Returns null if element is falsy.

Element configuration

SourceUse
data-urlRequest URL (default /).
data-methodHTTP method (default POST, upper-cased).
data-param-* + form fieldsParameters, via AviFlow.tools.element.getParams. Inherited through data-parent.
data-opt-pending-*Pending-state options, see togglePendingState.
data-on-beforeOptional hook called before the request is sent, see Hooks.
data-onShortcut for all the hooks below, see Hooks.
data-on-response / data-on-success / data-on-failOptional hooks called after the response, see Hooks.

opt is spread over the internal request options (headers, method, params, url, …), so it can override any of them.

Request behaviour

  • Always sends X-Requested-With: XMLHttpRequest.
  • GET / HEAD: params are appended to the URL query string.
  • POST / PUT: params are sent as FormData.
  • Other methods: params sent as JSON body with Content-Type: application/json; charset=UTF-8.
  • Before the request, the element's active content is set to pending (AviElement.setActiveContent(element, 'pending')). The action does not switch it back.
  • The element is put in pending state during the request and restored in finally.

Hooks

Each hook attribute holds the name of an action, resolved through flow.resolveAction and called as hook(payload, element, event, targetSelector, flow). Hooks are optional and are not awaited.

AttributeCalledPayload
data-on-beforeBefore the request is sent. Runs first, before the element's active content is set to pending and before the pending state is turned on.The request params (same object used for the query string / body).
data-on-responseHTTP 2xx and body parsed (JSON or HTML string).The parsed response.
data-on-successJSON response with a truthy success.The parsed response.
data-on-failJSON response with a falsy success.The parsed response.
Shortcut: data-on

data-on="name" is equivalent to setting every hook attribute to name followed by the hook:

data-on="trigger.on"
<!-- same as -->
data-on-before="trigger.on.before"
data-on-error="trigger.on.error"
data-on-fail="trigger.on.fail"
data-on-response="trigger.on.response"
data-on-success="trigger.on.success"

An explicit data-on-* attribute takes priority over the shortcut for that hook. A derived name that matches no registered action is skipped. data-on-error is read by the flow engine, not by this action.

If data-on-before throws, no request is sent and the error is thrown to the caller. Request errors are not handled by this action: they are thrown to the caller (when run by a flow, the engine passes them to data-on-error).

Response handling

ResponsePromise
HTTP status not 2xxRejects with Error("HTTP <status> <statusText>"). The body is not read and no response hook is called.
Content-Type contains text/htmlResolves with the response text (string).
OtherwiseParsed as JSON and resolved with the parsed object.
Network / parse errorRejects with the original error.
